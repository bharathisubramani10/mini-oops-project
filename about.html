Problem Statement & Objectives

In institutions, universities, and organizations, informal grievance handling (verbal complaints, physical letters, unmonitored emails) results in lost issues, lack of accountability, missed Service Level Agreements (SLAs), and zero visibility for complainants.

ResolveDesk solves this by centralizing complaint lodging, automated ticket dispatching, background SLA watchdog timers, and polymorphic escalation rules to ensure transparent, auditable redressal.

  • Multi-Category Registry: IT, Infrastructure, Academic, Laboratory, and Administration.
  • SLA & Priority Queue: Automated urgency ranking (Critical tickets served first).
  • Polymorphic Escalation: Automated reassignment when deadlines approach.
  • File I/O Stream Audit: CSV dataset export and batch ticket import.

10 Java OOP Concepts in ResolveDesk

How each theoretical concept operates naturally inside this Complaint Resolution System.

1. Encapsulation
Complaint Entity

Fields in Complaint (such as id, status, priority, slaDeadline) are declared private (data hiding). State mutations are guarded by validating setters that prevent illegal state transitions (e.g. jumping from OPEN directly to CLOSED without investigation notes).

private ComplaintStatus status;
public void setStatus(ComplaintStatus next) {
  if (!isValidTransition(this.status, next))
    throw new InvalidStatusTransitionException();
  this.status = next;
}
2. Inheritance
BaseEntity & User Roles

Entities inherit common audit timestamps (createdAt, updatedAt) from BaseEntity. Parent class User is extended by concrete subclasses: ComplainantUser (lodges issues), SupportOfficerUser (investigates), and SystemAdminUser (configures SLAs).

public class Complaint extends BaseEntity { ... }
public class ComplainantUser extends User { ... }
public class SupportOfficerUser extends User { ... }
3. Polymorphism
Method Overriding & Overloading

Method Overriding: Interface EscalationPolicyStrategy defines executeEscalation(Complaint), overridden differently by TechnicalEscalationStrategy, InfrastructureEscalationStrategy, and AcademicGrievanceStrategy.
Method Overloading: findComplaints(String id) vs findComplaints(Category cat, Priority prio).

@Override
public EscalationResult executeEscalation(Complaint c) {
  // Polymorphic SLA window and routing authority
}
4. Interfaces
Service & Exporters

Decoupled design via contracts: ComplaintService implemented by ComplaintServiceImpl, NotificationChannel implemented by EmailNotifier and SmsNotifier, and ReportExporter for CSV/PDF generation.

public interface ComplaintService {
  ComplaintDto fileComplaint(ComplaintDto dto);
  ComplaintDto updateStatus(String id, ComplaintStatus status);
}
5. Exception Handling
Custom Exceptions & Advice

Custom checked and unchecked domain exceptions: ComplaintNotFoundException, DuplicateTicketException, InvalidStatusTransitionException, and SlaBreachedException handled globally via Spring @ControllerAdvice.

@ControllerAdvice
public class GlobalExceptionHandler {
  @ExceptionHandler(ComplaintNotFoundException.class)
  public ResponseEntity<?> handleNotFound(...) { ... }
}
6. Collections Framework
List, Map, Set, PriorityQueue

ArrayList: Dynamic registry table traversal.
PriorityQueue: Orders tickets so that Critical severity and nearest SLA deadlines are processed first.
HashMap: Fast O(1) category count aggregation and in-memory ticket cache.
HashSet: Unique tracking tags and duplicate checking.

PriorityQueue<Complaint> slaQueue = new PriorityQueue<>(
  Comparator.comparing(Complaint::getSlaDeadline)
);
7. File Handling
CSV Streams & Buffer

Import: Reads CSV datasets with BufferedReader and FileReader, tokenizing fields and saving to database.
Export: Streams ticket audit logs to disk using BufferedWriter and FileWriter formatted with standard RFC 4180 commas.

try (BufferedWriter writer = new BufferedWriter(new FileWriter(file))) {
  writer.write("TicketID,Title,Priority,Status\n");
  ...
}
8. Real-World Threading
SLA Daemon & Runnable

Background SLA Watchdog Daemon runs on an ExecutorService or ScheduledExecutorService thread, periodically scanning tickets nearing SLA breach and dispatching alert emails without freezing the main HTTP web thread.

ScheduledExecutorService scheduler = Executors.newSingleThreadScheduledExecutor();
scheduler.scheduleAtFixedRate(new SlaWatchdogWorker(), 0, 15, TimeUnit.MINUTES);
9. Logging Framework
SLF4J & Logback

Enterprise logging via LoggerFactory.getLogger() across INFO, WARN, ERROR, and DEBUG levels with rotating file appenders (e.g. complaints-audit.log) rather than standard System.out.println().

private static final Logger log = LoggerFactory.getLogger(ComplaintService.class);
log.warn("Ticket #{} breached SLA threshold by {} hours", id, diff);
10. Event Handling
Spring ApplicationEvents

Decoupled Observer Pattern via Spring Events: ComplaintFiledEvent and ComplaintStatusChangedEvent published by ApplicationEventPublisher and caught asynchronously by @EventListener to send emails and SMS.

publisher.publishEvent(new ComplaintFiledEvent(ticket));

@EventListener
public void onComplaintFiled(ComplaintFiledEvent e) { ... }
